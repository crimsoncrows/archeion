# Archeion

**Archeion** (Greek for *official records repository*) is a Django-based web research repository with semantic similarity detection. It lets users browse and read research manuscripts, check submitted work for similarity against existing papers, and explore research trends over time.

---

## Features

- **Research repository** — browse, search, and view full manuscripts (PDF)
- **Semantic similarity detection** — BGE-M3 embeddings with cosine similarity, in three analysis modes:
  - Title
  - Abstract
  - Full text
- **Similarity feedback** — star-rating feedback on the results page (one submission per user, Post/Redirect/Get)
- **Trend analysis** — Chart.js visualizations, including heatmaps via `chartjs-chart-matrix`
- **Role-based access control** — students, professors, and administrators see different views
- **Admin dashboard** — custom `administratordb` app for user management, research paper CRUD, dashboard counters, and feedback review
- **Accounts** — registration, login, profile view/update, password change, and password reset by email

### Privacy

Files and text submitted for a similarity check are **not saved**. Only professors can see students' similarity results, and never the submitted file itself.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Backend | Django (Python) |
| Database | TiDB Cloud Serverless (MySQL-compatible) via PyMySQL |
| Embeddings | BGE-M3 (upgraded from an all-MiniLM-L6-v2 SBERT baseline) |
| PDF processing | pdfplumber, Docling |
| Media storage | Cloudinary (PDF uploads, 10 MB cap) |
| Static files | WhiteNoise |
| Email | Brevo via Anymail (production), Mailpit (local) |
| Charts | Chart.js + chartjs-chart-matrix |
| Frontend | Django templates, Bootstrap 5 (only where needed) |

---

## How Similarity Detection Works

1. Papers in the repository are split into chunks, embedded with **BGE-M3**, and the chunk vectors are averaged into one vector per paper. 
2. When a user submits text or a file, it is embedded the same way.
3. The submission is compared against stored embeddings using **cosine similarity**.
4. Functional and Feature matrix is generated by Claude Haiku.

## Getting Started

### Prerequisites

- Python 3.x
- Access to the team's TiDB database credentials
- Cloudinary account credentials
- (Optional) [Mailpit](https://mailpit.axllent.org/) for testing email locally

### Installation

```bash
git clone https://github.com/anjlalxn/archeion.git
cd archeion
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### Environment Variables

Create a `.env` file in the project root.

```env
SECRET_KEY=

TIDB_HOST=
TIDB_PORT=
TIDB_USER=
TIDB_PASSWORD=
TIDB_DB_NAME=

CLOUDINARY_NAME=
CLOUDINARY_KEY=
CLOUDINARY_SECRET=
CLOUDINARY_URL=

BREVO_API_KEY=
ANTHROPIC_API_KEY=


DEBUG=
ALLOWED_HOSTS=
DEFAULT_FROM_EMAIL=
```


### Run

```bash
python manage.py migrate
python manage.py collectstatic
python manage.py runserver
```

When `DEBUG=True`, password-reset emails go to Mailpit instead of Brevo.

### Run

Choose one of two ways to run Archeion.

```bash
python manage.py migrate
python manage.py collectstatic
```

#### Option A: `runserver` (local development)

Quickest setup. Only reachable on your own machine.

```bash
python manage.py runserver
```

Open http://127.0.0.1:8000. With `DEBUG=True`, password-reset emails go to Mailpit instead of Brevo.

#### Option B: Waitress + Cloudflare Tunnel (public access)

Use this to serve the site to others without port forwarding.

1. **Install Waitress** (skip if already installed)

   ```bash
   pip install waitress
   ```

2. **Download cloudflared**

   - Windows: `winget install --id Cloudflare.cloudflared`
   - macOS: `brew install cloudflared`
   - Linux / manual: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/

3. **Start the app with Waitress**

   ```bash
   waitress-serve --port=8000 <project_name>.wsgi:application
   ```

4. **Start the tunnel** (in a second terminal)

   Quick temporary URL, no account or domain needed:

   ```bash
   cloudflared tunnel --url http://localhost:8000
   ```

   Or, for a named tunnel on a domain you own:

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create archeion
   cloudflared tunnel route dns archeion <your-domain>
   cloudflared tunnel run --url http://localhost:8000 archeion
   ```

5. **Update your `.env`** with your public hostname:

   ```env
   DEBUG=False
   ALLOWED_HOSTS=<your-domain>,localhost,127.0.0.1
   ```

   If you hit CSRF errors on login, add `CSRF_TRUSTED_ORIGINS = ["https://<your-domain>"]` to `settings.py`.

> Static files are served by WhiteNoise in both options, so run `collectstatic --noinput` first.

# Running Archeion like runserver command

  To run Archeion without Cloudflare, add the following to the .env file:
  ```env
   BEHIND_CLOUDFLARE=False
   ```
Start the waitress command as usual to access the site via localhost, similar to the ```py manage.py runserver``` command. Otherwise, run ```cloudflared``` commands via terminal and change the variable to ```True.```

## Database Viewer and Query with Beekeeper Studio
Archeion uses TiDB as its main cloud database platform, backups and uptime are handled for the developers without hassle. You can access and view the data from the TiDB Dashboard or through Beekeeper Studio.

### How to Connect TiDB to Beekeeper Studio (FOR MYSQL DEMO)
1. Open Beekeeper Studio on your computer.
2. Click New Connection or the + button.
3. Select TiDB as the connection type.
4. Enter your TiDB connection details:
   - Host: Your TiDB server address
   - Port: 4000 (commonly used for TiDB Cloud)
   - Username: Your TiDB username
   - Password: Your TiDB password
   - Database: Your database name, if required
5. Configure SSL if your TiDB server requires it. (ENABLE)
6. Click Test Connection if available.
7. Click Connect.
8. Once connected, your databases and tables should appear in the sidebar.
   
### How to Disconnect TiDB from Beekeeper Studio
1. Open Beekeeper Studio.
2. Go to your active TiDB connection.
3. Find the Disconnect option in the toolbar or connection menu.
4. Click Disconnect. (IMPORTANT)
5. Confirm that the connection is no longer active.
   
> Note: Disconnecting only ends your database session. It does not delete your database or shut down the TiDB server.
